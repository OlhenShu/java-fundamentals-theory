    0Цілі теми

    Після цієї теми ви зможете пояснити, як вихідний код Java перетворюється на байткод і хто саме його виконує, а також чим JDK відрізняється від JVM. Ви встановите JDK поточної LTS-версії (Java 25), перевірите середовище командами java -version і javac -version та усвідомлено оберете інструмент: командний рядок, JShell чи IDE. Ви розумітимете, чому метод main має саме таку сигнатуру і як програма отримує аргументи командного рядка. Ви розрізнятимете вісім примітивних типів і посилальні типи та зможете передбачити результат цілочисельного ділення, переповнення й порівняння посилань. І нарешті, ви розкладете класи по пакетах, скомпілюєте й запустите свою першу програму з командного рядка.

    1Як виконується Java-програма

    Проблема. Програму ми пишемо звичайним текстом, а процесор розуміє лише двійкові інструкції. Ба більше, процесори й операційні системи різні: те, що зібрано для Windows на x64, не запуститься на macOS з ARM-процесором. Мовам на кшталт C доводиться компілювати програму окремо під кожну платформу.

    Чому Java робить інакше. Java розділяє шлях програми на два кроки. Спершу компілятор javac перевіряє вихідний код і перетворює файл .java на файл .class. У ньому не машинний код конкретного процесора, а байткод — проміжний формат, який людина вже не читає, але й до «заліза» він ще не прив’язаний. Потім лаунчер java запускає віртуальну машину Java (JVM), і саме вона виконує байткод на вашій платформі.

    Рішення. Отже, ви компілюєте один раз, а отриманий .class виконується всюди, де встановлена JVM. Якщо в коді є помилка, компілятор не створить .class-файл узагалі, тому багато проблем ви побачите ще до запуску.

    Коли це застосовувати. Завжди: це базовий цикл будь-якої Java-програми. IDE виконує ті самі два кроки автоматично, коли ви натискаєте «Run», тому розуміння цього циклу допомагає читати помилки, навіть якщо ви ніколи не набираєте javac вручну.

    Відмінності між версіями

    Починаючи з Java SE 11, маленьку програму можна запустити одним кроком — java Greeter.java: лаунчер скомпілює її в пам’яті й одразу виконає, не створюючи .class-файл. З Java SE 22 так можна запускати програму, розкладену по кількох файлах. Для навчання ми все одно спершу розбираємо два окремі кроки, бо саме так працюють збирачі проєктів та IDE.

    Джерело: dev.java — Getting Started with Java: The Compilation and Execution Cycle; dev.java — Launching Simple Source-Code Programs

    2JDK: що всередині і яку версію брати

    Проблема. Фраза «встановіть Java» звучить однозначно, але новачок швидко натрапляє на кілька абревіатур: JDK, JRE, JVM. Легко встановити не те й потім дивуватися, чому немає компілятора.

    Чому так. Історично існували два пакети. JRE (Java Runtime Environment) містив лише те, що потрібно для запуску готових програм, а JDK (Java Development Kit) — ще й інструменти для їх створення. Сьогодні окремий JRE ні OpenJDK, ні Oracle більше не поширюють, тож «завантажити Java» означає завантажити JDK. JVM — це не окремий продукт для завантаження, а частина JDK, яка виконує байткод.

    Рішення. Встановлюємо JDK. У його теці bin лежать інструменти, з якими ми працюватимемо в цій темі: компілятор javac, лаунчер java, інтерактивна оболонка jshell, генератор документації javadoc та архіватор jar. Разом з інструментами JDK містить стандартну бібліотеку класів — Java SE API, — з якої ми вже в першій програмі візьмемо String і System.

    Яку версію обрати. Нові версії Java виходять регулярно, але частина з них має статус LTS (Long-Term Support) і підтримується значно довше. Станом на кінець вересня 2026 року найновішим випуском є Java 27, а поточною LTS-версією — Java 25. Для курсу беремо саме Java 25: код і документація, на які ми посилаємося, відповідають цій версії, а довга підтримка означає, що встановлене зараз середовище прослужить вам увесь курс.

    Порада

    Домовтеся в групі про одну версію JDK. Коли у викладача Java 25, а у студента Java 17, приклади з новими можливостями мови просто не скомпілюються, і час піде на пошук «помилки», якої в коді немає.

    Джерело: dev.java — Getting Started with Java: Preparing the Execution of Your First Program; Java SE 25 — JDK Tool Specifications

    3Середовище та інструменти розробки

    Проблема. JDK встановлено, але команда javac у терміналі каже, що її не знайдено. Операційна система не шукає програми по всьому диску — вона дивиться лише в теки, перелічені у змінній середовища PATH.

    Рішення. Створюємо змінну JAVA_HOME, яка вказує на теку з JDK, і додаємо її підтеку bin до PATH. Команди нижче діють лише в поточному вікні терміналу — це зручно для першої перевірки. Щоб налаштування зберігалися постійно, їх задають у параметрах системи або в профілі оболонки.

    Після цього обидві команди мають вивести номер версії. Якщо java -version працює, а javac -version ні, найчастіше у PATH потрапила не тека JDK, а якась інша встановлена Java.

    Типова помилка

    Пробіл зайвий або пропущена крапка з комою в PATH — і Windows уже не знаходить javac. Чому: PATH — це рядок, де теки розділено символом ; (у Linux і macOS — :), і система читає його буквально. Перевіряйте результат командою echo %PATH% або echo $PATH.

    JShell: швидкі експерименти

    Проблема. Щоб перевірити, скільки буде 7 / 2, не хочеться створювати клас, метод main і компілювати файл. Рішення. JShell — інструмент JDK, що працює за принципом REPL (read-eval-print loop): ви вводите вираз чи оголошення, і він одразу показує результат. Коли застосовувати. Для перевірки окремих виразів і коротких ідей; повноцінні програми з пакетами все одно пишемо у файлах.

    Тут $1 — це змінна, яку JShell створив сам, щоб зберегти результат виразу.

    IDE

    Для великих проєктів розробники використовують інтегровані середовища розробки (IDE): вони самі компілюють код, підсвічують помилки ще під час набору та допомагають налагоджувати програму. Документація dev.java згадує безкоштовні IntelliJ IDEA, Eclipse і NetBeans. У курсі ви можете користуватися будь-якою з них, але першу програму варто скомпілювати й запустити саме з терміналу: так ви побачите кроки, які IDE потім виконуватиме замість вас.

    Джерело: dev.java — Getting Started with Java: Setting up a Java Development Kit; dev.java — JShell, the Java Shell Tool; dev.java — Getting Started with Java: Going Further

    4Точка входу в програму

    Проблема. У програмі можуть бути десятки класів і сотні методів. Коли ви пишете java HelloWorld, JVM має якось вирішити, з якого саме рядка почати.

    Чому так. Java домовляється про це раз і назавжди: лаунчер завантажує вказаний клас, готує його до роботи й викликає в ньому метод main. Кожне слово класичної сигнатури пояснює, як JVM має до нього достукатися. Модифікатор public означає, що метод доступний ззовні класу, — а лаунчер якраз ззовні. Слово static означає, що метод належить класу, а не окремому об’єкту, тож його можна викликати, нічого не створюючи. Тип void каже, що метод нічого не повертає. А параметр String[] args — це масив рядків, у який лаунчер кладе аргументи командного рядка.

    Рішення. Ми пишемо public static void main(String[] args) і розміщуємо інструкції програми всередині фігурних дужок цього методу. Вони виконуються згори донизу, рядок за рядком. Як оголошувати власні методи, ви дізнаєтеся в окремій темі; поки що нам достатньо одного — main, а готові методи стандартної бібліотеки, як-от System.out.println, ми лише викликаємо.

    Коли застосовувати. У кожній програмі, яку запускаєте командою java. Клас без main скомпілюється нормально, але запустити його лаунчер відмовиться — він просто не знайде, з чого почати.

    Java 25: нові форми main

    У Java 25 лаунчер розпізнає й простіші варіанти: main без параметрів і без static, а також «компактні» файли, де метод можна написати без оголошення класу, а друкувати через клас IO. Вони створені для перших кроків у мові, але в старіших версіях не компілюються, і в робочих проєктах ви бачитимете класичну форму. Тому в курсі використовуємо саме її; компактну форму показуємо лише для впізнавання:

    Типова помилка

    Метод названо Main або параметр оголошено як String args. Компілятор мовчить — це цілком законні методи, — але лаунчер шукає метод саме з іменем main і параметром-масивом, тож програма не стартує. Java чутлива до регістру: Main і main для неї різні імена.

    Джерело: JLS SE 25, §12.1.4 (Java Virtual Machine Startup); Java SE 25 — The java Command; Java SE 25 API — java.lang.IO

    5Типи даних: примітиви та посилання

    Навіщо змінній тип

    Проблема. Програма зберігає значення в пам’яті, і, щоб правильно з ними працювати, треба знати, що саме там лежить: ціле число, дробове, символ чи текст. Якщо дізнаватися про це лише під час виконання, помилку «додали текст до числа» можна виявити занадто пізно.

    Чому так. Java — мова зі статичною типізацією: кожну змінну треба оголосити разом із типом до першого використання. Тип визначає, які значення змінна може містити і які операції над ними дозволені. Компілятор перевіряє це ще до запуску.

    Рішення і коли застосовувати. Оголошуючи змінну, ми обираємо тип, що точно описує дані: кількість — int, прапорець — boolean, текст — String. Усі типи Java поділено на дві великі групи — примітивні та посилальні, — і різниця між ними визначає, що саме зберігається у змінній.

    Вісім примітивних типів

    Примітивний тип визначено самою мовою, і його назва — зарезервоване ключове слово. Змінна примітивного типу містить саме значення, і дві такі змінні ніколи не ділять спільного стану між собою.

    Чотири типи зберігають цілі числа й відрізняються лише розміром. byte займає 8 біт і вміщує значення від −128 до 127; short — 16 біт, від −32 768 до 32 767; int — 32 біти, від −2 147 483 648 до 2 147 483 647; long — 64 біти для справді великих чисел. За замовчуванням для цілих чисел використовуємо int, а long — коли діапазону int може забракнути, як-от для мілісекунд чи великих лічильників.

    Два типи зберігають числа з плаваючою крапкою: float (32 біти) і double (64 біти). Звичайний вибір — double. Обидва типи зберігають значення наближено, тож для точних грошових розрахунків вони не підходять — цю тему розберемо пізніше.

    Тип char займає 16 біт і зберігає одну кодову одиницю UTF-16 — фактично символ, записаний в одинарних лапках: 'A'. Важливо, що char у Java — це числовий тип без знака: у виразах з арифметикою символ поводиться як його числовий код. Нарешті, boolean має рівно два значення — true і false — і з числами не змішується.

    Літерали та значення за замовчуванням

    Проблема. Число 3000000000 не вміщується в int. Якщо просто написати long big = 3000000000;, компілятор відмовиться — і це дивує новачків, адже тип змінної long.

    Чому так. Цілий літерал без суфікса завжди має тип int, незалежно від того, куди його присвоюють. Компілятор перевіряє сам літерал ще до присвоєння.

    Рішення. Для long-літерала додаємо суфікс L: 3000000000L (велика літера, бо мала l легко плутається з одиницею). Для float — суфікс f: 2.5f. Довгі числа можна розбивати підкресленнями для читабельності: 3_000_125 — це те саме, що 3000125.

    Коли це важливо. Поля класу, які ви не ініціалізували, отримують значення за замовчуванням: 0 для чисел, false для boolean, '\u0000' для char і null для посилань. Але локальні змінні всередині методу такого значення не отримують: читання неприсвоєної локальної змінної — це помилка компіляції variable count might not have been initialized. Так Java захищає від випадкових «сміттєвих» значень.

    Джерело: JLS SE 25, §4.2 — Primitive Types and Values; JLS SE 25, §3.10.1 — Integer Literals; JLS SE 25, §4.12.5 — Initial Values of Variables; dev.java — Creating Primitive Type Variables in Your Programs

    Цілочисельна арифметика: ділення та переповнення

    Проблема. Студент очікує, що 7 / 2 дасть 3.5, а 2147483647 + 1 — 2147483648. Java друкує 3 і -2147483648, і жодної помилки не повідомляє.

    Чому так. Коли обидва операнди цілі, результат теж цілий: ділення відкидає дробову частину, округлюючи в бік нуля. Остача % має знак діленого. А при переповненні цілочисельні оператори не кидають винятків — значення просто «загортається» по колу в межах 32 біт. Єдиний виняток у цілочисельній арифметиці — ділення (або остача) на нуль, яке кидає ArithmeticException.

    Рішення. Якщо потрібен дробовий результат, хоча б один операнд має бути дробовим (7.0 / 2). Якщо результат може вийти за межі int, обчислюємо в long. Коли застосовувати: щоразу, коли ділите цілі числа або множите великі значення — секунди на мілісекунди, кількість на ціну в копійках.

    Лабораторія: змініть a і b

    Сторінка перераховує вивід за правилами Java для int і long. Спробуйте b = 0, від’ємні числа та a = -2147483648, b = -1.

    Вивід програми

    Що буде виведено?

    Обидві змінні отримують результат того самого ділення, але мають різні типи. Запишіть обидва рядки виводу.

    Що буде виведено?

    Символи теж беруть участь в арифметиці. Запишіть три рядки виводу.

    Джерело: JLS SE 25, §4.2.2 — Integer Operations; JLS SE 25, §15.17.2 — Division Operator /; JLS SE 25, §15.18 — Additive Operators

    Посилальні типи

    Проблема. Рядок, список чи будь-який інший складний об’єкт може займати багато пам’яті. Якби кожне присвоєння копіювало весь об’єкт, програма працювала б повільно й не змогла б поділитися одним об’єктом між різними частинами коду.

    Чому так. Тому для класів (і масивів) Java використовує посилальні типи. Об’єкт створюється окремо — наприклад, виразом new StringBuilder("Hi"), — а змінна зберігає лише посилання на нього, тобто «адресу», за якою об’єкт можна знайти. Коли ви присвоюєте таку змінну іншій, копіюється посилання, а не об’єкт. На один об’єкт може вказувати кілька змінних, і зміна через одну з них видна через усі інші. Особливе значення null означає «посилання нікуди не вказує».

    Рішення. Думайте про посилальну змінну як про ярлик на об’єкті, а не як про сам об’єкт. Оператор == для посилань порівнює саме ярлики: чи вказують вони на той самий об’єкт. Щоб порівняти вміст рядків, використовуйте метод equals.

    Коли застосовувати. Будь-яка змінна, тип якої — клас (String, StringBuilder, Scanner…) або масив (String[] args), є посилальною. Примітивних типів лише вісім, і вони пишуться з малої літери; все інше — посилання.

    Трасування: значення проти посилання

    Натискайте «Крок вперед». Підсвічено рядок, який щойно виконався; праворуч — стан після нього.

    Зверніть увагу на різницю. Присвоєння int copy = score скопіювало значення 10, тому зміна copy ніяк не вплинула на score. Присвоєння alias = message теж щось скопіювало, але це було посилання — і через alias ми змінили той самий об’єкт, на який вказує message. Тому обидва друкуються як Hi!, а message == alias дає true: це один об’єкт.

    Типова помилка

    Порівнювати рядки через ==. Іноді це «працює», бо однакові рядкові літерали у програмі можуть вказувати на один і той самий об’єкт, — і саме тому помилка підступна: рядок, прочитаний із клавіатури чи файлу, буде іншим об’єктом з тим самим вмістом, і == раптом дасть false. Для вмісту завжди first.equals(second).

    Джерело: JLS SE 25, §4.3.1 — Objects; JLS SE 25, §15.21.3 — Reference Equality Operators == and !=; JLS SE 25, §3.10.5 — String Literals; Java SE 25 API — String.equals

    6Пакети в Java: вступ

    Проблема. Поки програма складається з одного класу, все просто. Але в реальному проєкті сотні класів, і рано чи пізно двоє розробників назвуть свої класи однаково — скажімо, Report. До того ж у теці з сотнею файлів неможливо зорієнтуватися.

    Чому так. Пакет — це простір імен, що групує пов’язані класи. Повне ім’я класу складається з імені пакета та імені класу: com.example.intro.Greeter. Два класи Report у різних пакетах мають різні повні імена, тож конфлікту немає. Щоб імена пакетів у світі не перетиналися, їх за домовленістю будують від перевернутого доменного імені організації: com.example.

    Рішення. Першим рядком файлу (до нього можуть бути лише коментарі) пишемо оголошення package. Структура тек повторює ім’я пакета: класи пакета com.example.intro лежать у теці com/example/intro. Щоб використати клас з іншого пакета, або пишемо його повне ім’я, або імпортуємо клас оголошенням import і далі звертаємося коротким іменем. Класи пакета java.lang — String, System, Integer — імпортуються автоматично в кожен файл, тому ми ніколи не пишемо import java.lang.String.

    Власні класи в різних пакетах ми створюватимемо в наступних темах, а принцип зручно показати на класі зі стандартної бібліотеки. Клас LocalDate лежить у пакеті java.time, тож автоматично він не імпортується. У прикладі нижче першу змінну оголошено через import, а другу — через повне ім’я класу. Обидва способи дають той самий тип.

    Прапорець -d out каже компілятору класти .class-файли в теку out, створюючи там ту саму структуру тек за пакетами. Прапорець -cp out (скорочення від class path) каже лаунчеру, де шукати класи. Зверніть увагу: лаунчеру передаємо повне ім’я класу через крапки, а не шлях до файлу.

    Коли застосовувати. Завжди, крім найперших експериментів в одному файлі. Клас без оголошення package потрапляє в безіменний пакет, і з інших пакетів його неможливо імпортувати. Для навчальних «одноразових» програм це прийнятно, для проєкту — ні.

    Відмінності між версіями

    У Java 25 з’явилося оголошення import module, яке імпортує одразу всі пакети, експортовані модулем. Модулі — окрема велика тема, тож поки що ми імпортуємо окремі класи.

    Джерело: dev.java — Packages; JLS SE 25, §7.4 — Package Declarations; JLS SE 25, §7.5 — Import Declarations; JLS SE 25, §6.7 — Fully Qualified Names; Java SE 25 — The javac Command; Java SE 25 API — java.time.LocalDate

    7Моя перша програма

    Зберемо все разом: пакет, клас, точка входу, змінні примітивного й посилального типу. Програма Greeter будує привітання й рахує, скільки аргументів командного рядка їй передали. Спершу обчислюємо значення й зберігаємо їх у змінних з промовистими іменами, а друкуємо окремими рядками наприкінці — так код легше читати й трасувати.

    Спершу створіть файл src/com/example/intro/Greeter.java. Ім’я файлу має точно збігатися з іменем публічного класу, включно з регістром літер. Потім скомпілюйте та запустіть програму з кореня проєкту:

    Трасування: запуск java -cp out com.example.intro.Greeter alpha beta

    Лаунчер передає слова alpha і beta в масив args. Простежте, як змінюються змінні після кожного рядка.

    Спробуйте свої аргументи

    Уведіть аргументи так, як набрали б їх у терміналі. Слова, взяті в подвійні лапки, лаунчер отримує як один аргумент.

      Зверніть увагу на рядок "Arguments: " + count. Коли один з операндів + — рядок, інший (тут int) перетворюється на рядок, і відбувається конкатенація, а не додавання.

      Джерело: dev.java — Getting Started with Java: Compiling and Running Your First Java Program; JLS SE 25, §15.18.1 — String Concatenation Operator +; Java SE 25 — The java Command

      8Типові помилки та як їх уникнути

      Нижче — помилки, на які натрапляє майже кожен у перший тиждень. Для кожної важливо не лише запам’ятати правило, а й зрозуміти, чому Java поводиться саме так.

      Ім’я файлу не збігається з публічним класом

      Клас public class Greeter збережено у файлі greeter.java або Main.java. Компілятор відповідає class Greeter is public, should be declared in a file named Greeter.java. Чому: за публічним ім’ям компілятор і лаунчер знаходять файл класу, тож ім’я файлу — частина контракту. Як уникнути: називайте файл точно як публічний клас, з тим самим регістром.

      Запуск з розширенням .class

      Команда java Greeter.class не спрацює. Чому: лаунчер очікує ім’я класу, а не ім’я файлу; .class він сприймає як частину імені. Як уникнути: java -cp out com.example.intro.Greeter — повне ім’я класу, без розширення.

      Клас із пакетом запускають «зсередини» теки пакета

      Студент заходить у out/com/example/intro і виконує java Greeter. Чому не працює: клас насправді називається com.example.intro.Greeter, і лаунчер шукає його за шляхом com/example/intro/Greeter.class відносно class path. Як уникнути: запускайте з кореня проєкту, вказуючи -cp out і повне ім’я.

      Ціле ділення там, де потрібен дріб

      double average = total / count; для int total = 7 і int count = 2 дає 3.0. Чому: ділення виконується в int, і лише готовий результат 3 розширюється до double. Як уникнути: зробіть дробовим хоча б один операнд ще до ділення.

      Переповнення «до» присвоєння в long

      long millis = seconds * 1000; для великого int seconds дає від’ємне число. Чому: тип виразу визначають операнди, а не змінна ліворуч; множення двох int переповнюється раніше, ніж результат потрапить у long. Як уникнути: seconds * 1000L — літерал long змушує обчислення відбуватися в 64 бітах. Цей випадок ви детально розберете в міні-задачі.

      Читання неініціалізованої локальної змінної

      int count;, а потім System.out.println(count + 1); — не компілюється: variable count might not have been initialized. Чому: значення за замовчуванням отримують лише поля й елементи масивів, а локальна змінна має бути явно присвоєна до першого читання. Як уникнути: ініціалізуйте локальні змінні одразу при оголошенні.

      Порівняння рядків через ==

      Детально розібрано в розділі про посилальні типи: == перевіряє, чи це той самий об’єкт, а equals — чи однаковий вміст. Для тексту майже завжди потрібне друге.

      Джерело: dev.java — Getting Started with Java: Common Problems and Their Solutions; JLS SE 25, §7.6 — Top Level Class and Interface Declarations; JLS SE 25, Chapter 16 — Definite Assignment

      9Міні-задача: звіт про тривалість

      Умова. Таймер повертає тривалість як ціле число секунд int totalSeconds. Напишіть клас DurationReport у пакеті com.example.intro, який для totalSeconds = 3_000_125 друкує два рядки: тривалість у форматі «години h хвилини min секунди s» та загальну кількість мілісекунд.

      Вимоги до структури: кожну величину обчисліть в окрему змінну з промовистим іменем (hours, minutes, seconds, millis) і підберіть для кожної відповідний тип, а друкуйте лише наприкінці, коли всі значення вже пораховано. Очікуваний вивід:

      Підказка

      У годині 3600 секунд, у хвилині — 60. Цілочисельне ділення / відповідає на питання «скільки повних одиниць», а остача % — «скільки лишилося». Для мілісекунд подумайте, якого типу буде вираз totalSeconds * 1000 і чи вміститься в нього 3 000 125 000.

      Пояснення. Години — це кількість повних 3600-секундних блоків: 3000125 / 3600 = 833. Щоб знайти хвилини, спершу беремо залишок секунд після повних годин (3000125 % 3600 = 1325), а вже його ділимо на 60 — виходить 22. Секунди — залишок від ділення на 60: 5. Дужки в рядку з minutes формально не обов’язкові, бо % і / мають однаковий пріоритет і виконуються зліва направо, але вони роблять намір очевидним.

      Найцікавіше — millis. Змінна має тип long, але цього недостатньо: якщо написати totalSeconds * 1000, множення двох int переповниться до присвоєння, і ви отримаєте -1294842296. Суфікс L робить другий операнд long, тож totalSeconds розширюється і все множення відбувається в 64 бітах. У першому println ліворуч стоїть рядок "Duration: ", тож кожен наступний + — це конкатенація, і числа перетворюються на текст.

      Перевірте на інших значеннях

      Змініть кількість секунд: сторінка покаже вивід рішення та те, що надрукував би варіант без суфікса L.

      Вивід рішення
      Якби було long millis = totalSeconds * 1000;

      10Квіз: 10 питань

      Оберіть одну відповідь у кожному питанні. Якщо перша спроба не влучна, ви отримаєте навідне запитання і зможете спробувати ще раз, але в підсумковий бал зараховується лише перша відповідь.
